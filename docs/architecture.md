# Architecture

## Overview

SaveSphere is a **modular monolith**: one NestJS API holds all business logic, and the SvelteKit app
is a UI that talks to it through a same-origin proxy (`/api/*`). Future clients (Telegram/WhatsApp
bots, a background worker) reuse the same API modules and `packages/core`.

```
Browser (PWA) ──▶ web (SvelteKit) ──/api/*──▶ api (NestJS) ──▶ PostgreSQL 18
                                               │
                                               └──▶ AI provider (optional, per-user key)
```

## Layers inside the API

```
controller  → validates input with a shared Zod contract, maps HTTP
service     → use case: authorization by user, orchestration, transactions
core        → pure rules (Money, ledger entries); no I/O, fully unit-tested
db          → Drizzle schema + queries
```

- Every response is an envelope: `{ success: true, data }` or
  `{ success: false, error: { code, message, details? } }`. Error codes live in
  `packages/contracts` (`ErrorCode`), so the web app can branch on them.
- Every route requires a session unless marked `@Public()`. `@CurrentUser()` gives the user, and
  every query is scoped by `user_id`.

## Data model principles

- **Money is integer minor units** (`bigint` in the database, a safe-integer number in JSON).
  Floats are never used.
- **Double-entry ledger:** a `transactions` row (header) has one or more `transaction_entries`
  (signed amount per account). An expense or income has 1 entry, a transfer has 2. Balances are
  **derived** from entries, never stored. Cross-currency transfers are two entries in different
  currencies.
- **Tenant safety in the database:** child tables reference parents through `(user_id, id)`
  composite foreign keys, so Postgres rejects links across users even if application code has a
  bug. The integration tests cover this.
- **UUIDv7** primary keys generated by Postgres 18 (`uuidv7()`): time-ordered and index-friendly.
- **3NF**, with two deliberate, documented exceptions: `recurring_rules.next_run_on` (a scheduling
  cache) and the `jsonb` snapshots on reports and purchase evaluations (historical records that must
  not change when the underlying data changes).
- Soft delete only on `transactions` (needed for undo and offline sync). Other entities are
  archived (`archived_at`).
- Idempotent creation: `transactions.client_ref` is unique per user, so offline retries never
  create duplicates.

Schema: `packages/db/src/schema/*`. Migrations: `packages/db/migrations` (generated, never
hand-edited after merge).

## Optional AI

AI is **opt-in per user** (bring your own key), with an optional instance-wide key as fallback.

Resolution order (`AiCapabilityService`):
user opted out → user's active key → instance key → unavailable (`not_configured` / `invalid_key`).

- `GET /api/me/capabilities` tells the UI what is available.
- AI-only endpoints use `@RequiresAi()`, which returns `403 AI_NOT_CONFIGURED`.
- In the UI, AI-only features are wrapped in `<AiGate>`: **visible but locked**, with an explanation
  and a link to settings.
- Hybrid features (insights, reports, "can I afford it?") must work without AI using rules, and use
  AI only to add explanations.
- Keys are encrypted with AES-256-GCM (versioned master key), validated with a test call before
  saving, and never returned (only `••••abcd`).
- The numbers always come from code; AI only explains them.
- `AI_PROVIDER_MODE=fake` swaps in a deterministic adapter for tests and local UI work.

## Chat channels

Telegram and WhatsApp are optional and gated the same way: a channel is offered only when the
instance has its credentials, and it shows as locked otherwise.

## Web

- SvelteKit 3 with adapter-node. `hooks.server.ts` proxies `/api/*`, forwarding the client IP so
  auth rate limiting works per user, then resolves `locals.user` from the session cookie
  (`GET /api/me`).
- Routes: `(auth)` holds sign-in and sign-up, and redirects signed-in users home. `(app)` holds
  everything else behind the session guard in `(app)/+layout.server.ts`, inside the app shell
  (desktop sidebar; mobile top bar, bottom bar and "More" drawer, configured in
  `src/lib/navigation.ts`).
- Auth forms are form actions that call Better Auth through `event.fetch`, so the session cookie
  reaches the browser and they work before hydration (credentials never end up in a URL).
  Sign-out is a `POST /logout`.
- Origin: SvelteKit 3's adapter has no runtime `ORIGIN`. The server derives it from the `Host`
  header plus `X-Forwarded-Proto` (`PROTOCOL_HEADER`), which Traefik sets; it's needed for the
  CSRF check on form posts.
- Design system: tokens in `src/routes/layout.css` (`@theme`), taken from the Stitch project
  "Expense and Budget Tracker". Use the Material 3 role classes (`bg-surface`,
  `text-on-surface-variant`, `bg-primary-container`…) and the `card` utility, never raw colors.
  Fonts are self-hosted (Inter, Plus Jakarta Sans); icons are Material Symbols via
  `unplugin-icons` (`import Icon from '~icons/material-symbols/<name>'`).
- PWA: `static/manifest.webmanifest` plus `src/service-worker.ts`. The app shell is cached;
  `/api/*` is never cached.
- i18n with Paraglide. Locale comes from a cookie, then the browser language. Every string goes in
  both `messages/en.json` and `messages/es.json`.
